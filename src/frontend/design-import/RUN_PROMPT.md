# 실행 프롬프트 (Claude Code에 그대로 붙여넣기)

사용 순서
1. 이 `handoff` 폴더의 파일 전체를 로컬 리포지토리 `src/frontend/design-import/` 에 덮어쓰기
2. 리포지토리 루트에서 Claude Code 실행
3. 아래 프롬프트 ① 붙여넣기 → 분석 결과 확인 → 프롬프트 ② 입력

## ① 분석 (코드 수정 금지)
```
src/frontend/design-import/ 의 "생기포털 v3.dc.html" 이 갱신됐어. 같은 폴더의 CHANGES_2026-11-24.md 를 먼저 읽어줘. 이번 작업은 "통합 로드맵(mTRM) 차트" 한 화면을 실제 프론트 코드에 반영하는 거야.

지금은 분석만 하고 코드는 수정하지 마.
1. CHANGES_2026-11-24.md 와 git diff 를 대조해서 바뀐 내용을 요약하고, 문서에 없는 변경이 diff에 있으면 알려줘.
2. 통합 로드맵 차트에 해당하는 우리 프론트 코드의 파일/컴포넌트(필터 영역, 간트 격자, 막대, 툴팁)를 찾아서 알려줘. 없으면 "없음"이라고 알려줘.
3. 소스의 RM_LANES 데이터 구조(분과, 로드맵/상세과제, row, m, milestones, p4)를 우리 API/타입으로 어떻게 매핑할지 제안해줘. P2 실적(계획) 시작일, P3 완료일, P4 여부는 별도 필드가 필요한지도 알려줘.
4. 파일별 변경 계획을 표로 보여주고 멈춰줘. 내가 "진행"이라고 하기 전에는 파일을 수정하지 마.
```

## ② 구현 (분석 확인 후)
```
진행. CHANGES_2026-11-24.md 의 1~5번 항목을 구현해줘.
- 필터: 분과/진행상태/기간(연도 2칸)을 라벨 셀 형태로, 기간은 "조회" 버튼을 눌러야 적용. "상세검색" 버튼, 범례는 단일색.
- 격자: 분기/월 보기 모두 폭 1800px 고정 + 가로 스크롤, 분과 이름 칸 왼쪽 고정. 내부는 항상 6년(72개월) 컬럼이고, 조회 기간이 짧아도 칸 폭은 동일하며 기간 밖은 빈 공간.
- 막대: 로드맵(청록) 아래에 연계 상세과제(초록). 겹치지 않는 기간의 과제는 같은 줄에 나열. 분과 미매핑 과제는 맨 아래 별도 행.
- 진행상태: P1~P3은 항상, P4는 특수 케이스만. 완료 단계 마름모는 막대 왼쪽, 남은 단계는 막대 오른쪽(흰 마름모). 기간이 짧거나 뒤따르는 과제와 겹치면 단계를 막대 아래 줄로 내림.
- 툴팁: 계획일정/완료일정/등록일 + P1~P4 진행상태 표.

규칙
- .dc.html 코드를 그대로 복사하지 말고 우리 프로젝트의 컴포넌트·스타일 규칙으로 다시 작성하고, 문구·색상·간격은 소스와 똑같이 맞춰줘.
- 샘플 데이터(RM_LANES)는 mock 파일로 분리해줘.
- 막대 위치/겹침 계산은 월 컬럼 기준 순수 함수로 분리해줘.
- 기존 동작은 유지하고, 소스와 다르게 구현해야 하는 부분은 먼저 물어봐줘.
- 끝나면 변경한 파일 목록과 확인 방법을 알려줘.
```

## ③ 확인 요청 (구현 후)

```
CHANGES_2026-11-24.md 의 "적용 체크리스트" 항목별로 구현 여부를 O/X 표로 알려주고, X 항목이 있으면 이유와 남은 작업을 알려줘.
```
