# 화면설계서(와이어프레임) 템플릿

이 문서는 화면설계서 템플릿(PDF 샘플, 1슬라이드 = 1화면)의 구조를 마크다운으로 정리한 것입니다.
Claude Code가 화면설계서를 자동 생성/작성할 때 이 구조를 그대로 따라 각 화면(SCR-XXX)마다 하나의 섹션을 채우면 됩니다.

> 본 문서의 "1-5. 고정 사이즈/비율" 및 "5. HTML 구현 규격"은 실제 구현체인
> [화면설계서_부품공정자동화현황_샘플.html](화면설계서_부품공정자동화현황_샘플.html) (SCR-001~014, MTRM-MAIN 15개 화면 수록)의
> 실측 CSS 값을 그대로 역기재한 것입니다. 새 화면을 HTML로 만들 때는 이 문서의 값이 아니라
> 반드시 위 HTML 파일의 기존 CSS 클래스(`meta-box`, `desc-table`, `desc-continue`, `screen-section` 그리드 등)를
> 그대로 재사용합니다 — 클래스를 새로 만들거나 값을 임의로 바꾸지 않습니다.

## 1. 슬라이드(화면) 레이아웃 구조

> ⚠️ **레이아웃 구조와 사이즈는 화면마다 절대 변경하지 않습니다.**
> 헤더·캔버스·설명·푸터 4개 영역의 위치·비율은 모든 SCR-XXX 화면에 동일하게 고정 적용합니다. 화면마다 달라지는 것은 오직 **내용(텍스트, 와이어프레임 요소, 설명)** 뿐이며, 영역의 크기·위치·순서는 절대 재배치하거나 리사이즈하지 않습니다.

한 화면은 아래 4개 영역으로 구성되며, 이 구조는 모든 화면에서 동일하게 고정됩니다.

| 영역 | 위치 | 내용 | HTML 클래스 | 고정/가변 |
|---|---|---|---|---|
| 헤더(Header) | 상단, **좌측 캔버스 폭(76%)까지만** — 전체 폭이 아니라 처음부터 우측 Description과 분할됨 | Screen ID 뱃지, 화면명, URL, 상태 정보 | `.meta-box` | 가로·세로 고정 |
| 캔버스(Canvas) | 좌측 76%, 헤더 하단 | 실제 와이어프레임(화면 UI 목업)이 그려지는 공간 | `.wireframe-wrap` | 가로 고정, 세로 고정 폭(min-height) |
| 설명(Description) | 우측 24%, **헤더 행부터 하단까지 세로 전체** | 화면 요소에 대한 번호별 상세 설명 표 | `.desc-wrap` > `.desc-table` | 상단 타이틀+표 헤더는 고정, 데이터 행(상세설명 내용)은 가변 |
| 푸터(Footer) | 설명 영역 최하단, 설명 영역과 동일 폭 | 다음 화면으로 이어지는지 여부 표시 | `.desc-continue` | 가로·세로 고정 |

> 첨부 PDF 원본 템플릿 기준: 헤더는 전체 폭을 가로지르지 않고 좌측 캔버스 폭까지만 걸리며, 그 오른쪽에는 처음부터 검은 "Description" 타이틀 바가 시작된다. 즉 헤더 행 자체가 좌(캔버스)/우(설명) 두 칼럼으로 분할되어 있다 — 이 구조는 [화면설계서_부품공정자동화현황_샘플.html](화면설계서_부품공정자동화현황_샘플.html)에도 그대로 반영되어 있다(`.desc-wrap`이 `grid-row: 1 / -1`로 헤더 행부터 세로 전체를 차지).

### 1-1. 헤더(Header) 영역 — `.meta-box`

- **⚠️ 헤더는 화면 전체 폭이 아니라 좌측 캔버스 폭(76%)까지만 차지한다.** 우측 24%는 헤더 행에서부터 이미 Description 영역(검은 "Description" 타이틀 바)이 시작된다.
- **Screen ID**: 화면 고유 번호. 뱃지(박스) 형태로 좌측에 표시. 예: `SCR-001` (`.screen-id-badge`)
- **Screen**: 화면명(한글 명칭). 예: `부품 공정 자동화 현황`
- **URL**: 해당 화면의 라우트/경로. 예: `/portal/automation/parts`
- **Status**: 화면 설계 진행 상태. 예: `와이어프레임 (샘플, 보정 예정)`
  - 상태값 예시: `와이어프레임`, `시안 확정`, `개발 완료`, `검수 중` 등 프로젝트에서 정의한 값 사용
- 4개 항목은 가로 1행에 `gap:16px`로 나열(Screen ID 뱃지 → Screen 라벨/값 → URL 라벨/값 → Status 라벨/값 순서 고정)
- 헤더의 가로(76%)·세로(내용 기준 고정 높이) 크기는 화면마다 절대 변경하지 않는다.

**HTML 마크업 (그대로 복사해서 사용):**

```html
<div class="meta-box" style="margin:8px 24px 0 24px;">
  <div style="display:flex; align-items:center; gap:16px; flex-wrap:wrap;">
    <span class="screen-id-badge">SCR-XXX</span>
    <div><span class="meta-label">Screen</span><div class="meta-value" style="font-weight:600; font-size:15px;">{화면명}</div></div>
    <div style="margin-left:24px;"><span class="meta-label">URL</span><div class="meta-value">{/경로}</div></div>
    <div style="margin-left:24px;"><span class="meta-label">Status</span><div class="meta-value">{상태값}</div></div>
  </div>
</div>
```

### 1-2. 캔버스(Canvas) 영역 — `.wireframe-wrap`

- **가로·세로 사이즈 고정.** 화면 좌측(폭 76%, 헤더와 동일 폭)을 차지하는 와이어프레임 콘텐츠 영역
- 실제 UI 와이어프레임(버튼, 표, 차트, 입력폼 등 목업 요소)을 배치하는 공간
- 배경 `#f2f2f2`, 테두리 `1px solid #ccc`, 최소 높이 800px(`min-height:800px`) — 이 최소 높이가 화면별 캔버스의 고정 기준값
- 캔버스 내 요소에는 번호 인디케이터(`.indicator` 또는 `.indicator-el`)를 붙여 Description의 NO와 매칭

### 1-3. 설명(Description) 영역 — `.desc-wrap` / `.desc-table`

우측(폭 24%, 헤더 행부터 하단까지 세로 전체)에 위치한 표. 캔버스에 배치된 UI 요소를 번호로 매칭하여 설명한다.

- **상단 "Description" 타이틀 바 + "NO/상세설명" 표 헤더(`<thead>`)까지는 고정** — 모든 화면에서 동일한 위치·크기·스타일(검은 배경, 흰 글자)로 반복된다.
- **표 본문의 데이터 행(각 NO별 상세설명 내용)은 가변** — 영역 개수와 설명 분량에 따라 행 수·높이가 화면마다 달라진다. 내용이 길어지면 다음 화면 섹션(`-cont-1`, `-cont-2`)으로 이어진다(1-3절 하단 "오버플로우 처리" 참고).

| NO | 상세설명 |
|---|---|
| 1 | (캔버스 내 ① 요소가 속한 영역에 대한 설명) |
| 2 | (캔버스 내 ② 요소가 속한 영역에 대한 설명) |
| 3 | (캔버스 내 ③ 요소가 속한 영역에 대한 설명) |

**Description 셀 작성 표준 형식** (2026-08-13 확정, 모든 화면에 동일 적용):

1. **영역명** — `영역명:` 레이블 뒤 영역 이름, 다음 줄에 `ㄴ`로 시작하는 현재 영역 전체의 기능 설명 문장.
2. **요소** — 영역에 속한 요소가 2개 이상이면 `요소:` 레이블 뒤에 번호를 붙여 요소명을 노출한다. 번호 형식은 `영역NO-요소순번`(예: `1-1`, `1-2`). **요소가 1개뿐이면 요소번호는 붙이지 않고 요소명만 쓴다**(예: `요소: 조건 필터 & 조회 버튼`).
3. 각 요소별로 아래 항목을 순서대로 작성하되, 해당 사항이 없는 항목은 생략한다:
   - 노출조건 / 입력조건 / 출력조건 / 인터랙션 / 예외 Case 처리(각 Case별 alert 문구 포함) / 관리자 화면 연동 처리 / Back-end 연동 처리
4. **표 구조 원칙**: **NO 컬럼에는 영역 번호만** 넣는다(`1`, `2`, `3` …, `1-1` 금지). **한 영역 = 표에서 한 행(tr)** — 요소가 여러 개여도 행을 나누지 않고 영역명 설명 + 요소1 + 요소2 + … 를 모두 한 `<td>` 안에 이어서 담는다.
5. **영역명, 요소명, 요소별 NO는 볼드 처리**한다(`<b>영역명: 탭 영역</b>`, `<b>요소: 1-1 부품 공정 탭</b>`처럼 레이블+값 전체를 굵게).
6. 모든 문구는 좌측 상단 정렬(`text-align:left; vertical-align:top`).
7. **오버플로우 처리**: 한 영역(행)의 내용이 캔버스 높이를 넘으면, 넘친 지점(청크 단위: 영역명 인트로 또는 요소 단위)부터 다음 화면 섹션(`{SCR-ID}-cont-1`, `-cont-2` …)으로 이어서 노출한다. 이어지는 행은 같은 NO 값을 그대로 반복하고 `cont-row` 클래스(점선 상단 테두리)를 붙인다. 항목(NO) 단위 분할이 아니라 영역 내부의 청크 단위 분할이다.

**HTML 마크업 (그대로 복사해서 사용):**

```html
<div class="desc-wrap" style="margin:0 24px 24px 24px;">
  <h3 style="font-size:16px; font-weight:700; color:#212529; margin:0 0 12px 0;">Description</h3>
  <table class="desc-table">
    <thead><tr><th class="num">NO</th><th>상세설명</th></tr></thead>
    <tbody>
      <tr>
        <td class="num">1</td>
        <td>
          <b>영역명: {영역명}</b><br>ㄴ {영역 전체 기능 설명}<br><br>
          <b>요소: {번호 또는 생략} {요소명}</b><br>
          <span class="cond-label">노출조건:</span> {설명}<br>
          <span class="cond-label">입력조건:</span> {설명}<br>
          <span class="cond-label">출력조건:</span> {설명}<br>
          <span class="cond-label">BE 연동:</span> {API 경로 등}
        </td>
      </tr>
      <!-- 영역 수만큼 <tr> 반복 -->
    </tbody>
  </table>
  <div class="desc-continue">다음 화면에 계속 ▼</div> <!-- 이어지는 내용이 없으면 이 줄 생략 -->
</div>
```

### 1-4. 푸터(Footer) 영역 — `.desc-continue`

- 설명(Description) 영역 하단에 `다음 화면에 계속 ▼` 문구
- 한 화면 설명이 여러 섹션(`-cont-1`, `-cont-2` …)에 걸쳐 이어질 경우에만 표시
- 마지막 이어짐 섹션(더 이상 이어지는 내용이 없는 경우)에는 생략

### 1-5. 고정 사이즈/비율 (변경 금지, HTML 실측값 기준 — 2026-08-20 PDF 원본 대조 후 재확정)

| 영역 | 가로(폭) | 세로(높이) | 고정/가변 | 비고 |
|---|---|---|---|---|
| 상단 탭 내비게이션(`#tab-nav`) | `position:fixed; left:0; right:0` → 화면 전체 폭(100vw) | 고정 px 값 없음 — `padding:8px 16px` + `.tab-btn` 콘텐츠 높이로 자동 결정 | 고정(위치), 높이는 auto | PDF 원본 템플릿(4영역 구조)에는 없는 요소 — HTML 문서 열람용 화면 전환 내비게이션. `.screen-section`에 `scroll-margin-top:48px`로 이 탭 높이만큼 여백 확보 |
| 헤더(`.meta-box`) | **좌측 76%만**(`grid-column: 1`) — 전체 폭 아님 | 콘텐츠 높이 기준 고정 | **가로·세로 고정** | Screen ID 뱃지 + Screen/URL/Status 3열, margin `8px 24px 0 24px`. 우측 24%는 헤더 행에서부터 이미 Description 타이틀 바 |
| 캔버스(`.wireframe-wrap`) | 좌측 76%(`grid-column: 1`) | `min-height: 800px` | **가로·세로 고정**(최소 기준값) | 헤더 하단 ~ 하단 전 |
| 설명(`.desc-wrap`) | 우측 24%(`grid-column: 2`), **헤더 행부터 하단까지 세로 전체**(`grid-row: 1 / -1`) | 상단 "Description" 타이틀 + 표 헤더(`<thead>`)는 고정, **데이터 행(상세설명 내용)만 가변** | 폭 고정 / 상단 고정 + 본문 가변 | 좌측 `border-left:2px solid #dee2e6`, padding 16px |
| 푸터(`.desc-continue`) | 설명 영역과 동일 폭 | 콘텐츠 높이 기준 고정(문구 1줄 고정 서식) | **가로·세로 고정** | 설명 표 바로 아래, `padding:8px 10px` |

> **정정 이력**: 최초 작성 시 "헤더는 전체 폭"으로 잘못 기재했던 것을 첨부 PDF 원본 재대조 후 정정함(헤더는 좌측 76%까지만, 우측은 헤더 행부터 Description 시작). 이에 맞춰 HTML(`화면설계서_부품공정자동화현황_샘플.html`)의 그리드 CSS도 함께 수정하고 46개 화면 섹션 중 대표 화면(SCR-001 기본/팝업, SCR-014 상세뷰, MTRM-MAIN)을 Playwright로 스크린샷 검증했다.

핵심 CSS(변경 금지 — HTML `<style>` 블록에 이미 정의됨, 새 화면 추가 시 재사용만 함):

```css
.screen-section:not(#cover-page) {
  display: grid;
  grid-template-columns: 76% 24%;
  grid-template-rows: auto 1fr;
}
.screen-section:not(#cover-page) .meta-box { grid-column: 1; grid-row: 1; }
.screen-section:not(#cover-page) .wireframe-wrap { grid-column: 1; grid-row: 2; }
.screen-section:not(#cover-page) .desc-wrap {
  grid-column: 2; grid-row: 1 / -1;
  padding: 16px; border-left: 2px solid #dee2e6; background: #fff;
}
```

> `.desc-wrap`이 `grid-row: 1 / -1`로 헤더 행부터 세로 전체를 차지하기 때문에, 내부 최상단의 `<h3>Description</h3>`(1-3절 마크업 참고)가 자연히 헤더와 나란한 높이에서 시작된다 — 46개 화면 섹션의 `<h3>` 마크업 위치는 그대로 두고 이 전역 CSS 3줄만으로 처리했다.
>
> 위 비율/좌표 값은 화면 수·내용과 무관하게 모든 SCR-XXX 화면에서 동일하게 유지되어야 합니다.

### 1-6. PDF/PPTX 내보내기 시 사이즈 처리 방식 (2026-08-20 실측 검증)

HTML 화면과 PDF/PPTX 다운로드 결과를 비교하면 **절대 px 크기는 매체마다 다르지만, 76%/24% 레이아웃 비율 자체는 왜곡되지 않는다.** Playwright로 `.meta-box`/`.wireframe-wrap`/`.desc-wrap`의 실제 폭 비율을 화면 모드와 `applyPrintScaling()` 적용 모드에서 각각 측정해 확인했다.

| 매체 | 기준 폭 측정 방식 | 76%/24% 비율 유지 여부 |
|---|---|---|
| HTML(브라우저 화면) | 뷰포트 폭에 따라 반응형 | 기준(원본) |
| PDF(`downloadPDF`→`window.print()`) | `document.body.width`를 `@page`(13.33×7.5in, 여백 0.2in) 기준 px로 강제 고정 후, 섹션별 `scrollWidth`/`scrollHeight`에 맞춰 `zoom` 배율 적용(`applyPrintScaling()`) | **유지됨** — `zoom`은 가로세로 동일 배율의 fit-to-page 스케일링이라 비율을 왜곡하지 않음(실측: `.wireframe-wrap` 0.76, `.desc-wrap` 0.24로 화면과 동일) |
| PPTX(`downloadPPTX`) | `document.body.width`를 1680px로 강제 고정(표+사이드바+Description 패널이 겹치지 않을 최소 폭) 후, 섹션별 `Math.min(SLIDE_W/sw, SLIDE_H/sh)` 단일 배율로 fit-to-slide | **유지됨** — 동일한 이유(가로세로 동일 배율) |

- **왜 절대 크기가 달라 보이는가**: HTML은 브라우저 창 크기, PDF는 1244px(13.33in-0.4in 여백 환산), PPTX는 1680px로 각각 다른 "측정 기준폭"에서 76%/24%를 계산하기 때문에, 매체마다 헤더/캔버스/설명의 실제 픽셀 크기(px)는 다르게 나온다. 이는 **의도된 정상 동작**이다 — PDF는 16:9 슬라이드 규격(PPT와 동일 비율)에 맞추기 위해, PPTX는 표·사이드바·Description 패널이 겹치지 않는 여유 폭을 확보하기 위해 각각 별도 기준폭을 쓴다.
- **헤더(`.meta-box`)가 캔버스보다 좁아 보이는 이유**: 버그가 아니라 디자인 의도다. `.wireframe-wrap`(캔버스)은 좌우 margin이 없어(`margin:8px 0`) grid 트랙(76%) 폭을 그대로 채우는 반면, `.meta-box`(헤더)는 좌우 24px 카드 여백(`margin:8px 24px 0 24px`, 인쇄 시 `margin:0 24px`)이 있어 트랙 폭보다 48px 좁게 렌더링된다. 이 여백값(좌우 24px)은 화면과 인쇄 모두 동일하므로 매체 간 차이가 아니다.
- **결론**: 76%/24% 그리드 비율 자체를 고치는 코드 수정은 필요하지 않다(실측으로 비율 왜곡이 없음을 확인). "레이아웃이 다르게 보인다"는 인상은 매체별 절대 px 크기 차이(의도된 스케일링)에서 온 것이며, 이 절을 통해 그 이유를 문서화해 향후 동일한 의문이 재발하지 않도록 한다.

### 1-7. PDF 다운로드 시 실제로 발견·수정된 버그 — APPENDIX 화면 깨짐 (2026-08-20)

위 1-6절과 별개로, 실제 PDF 다운로드에서 **APPENDIX 예외Case/Alert 모음 (1/2, 2/2)** 두 화면이 깨지는 버그가 사용자 제보로 발견되어 수정했다.

- **증상**: PDF로 내보내면 APPENDIX 화면(`#appendix-exceptions`, `#appendix-exceptions-2`)의 표가 우측 24% 폭 안에만 눌려 들어가고, 좌측 76%는 텅 비어 보임.
- **원인**: 이 두 화면은 `.desc-wrap`(Description)이 없는 **예외적인 "전체 폭 1단 표" 레이아웃**으로, `<div id="appendix-exceptions" class="screen-section" style="display:block; grid-template-columns:1fr;">`처럼 인라인 스타일로 76%/24% 그리드를 쓰지 않도록 되어 있었다. 그런데 `@media print`의 `.screen-section:not(#cover-page) { display: grid !important; grid-template-columns: 76% 24% !important; }` 규칙이 특정도 (0,1,1,0)(class 1 + `:not()` 안의 id 1)으로, 인라인 스타일보다 강하게 적용되어 인쇄 시에만 강제로 2단 그리드로 뒤바뀌었다. HTML 화면에서는 문제없이 보이고 PDF에서만 깨졌던 이유가 이것이다.
- **수정**: `@media print` 블록에 `#appendix-exceptions#appendix-exceptions, #appendix-exceptions-2#appendix-exceptions-2 { display: block !important; grid-template-columns: 1fr !important; }`를 추가했다. 같은 id를 두 번 반복하는 CSS 특정도 트릭으로 (0,2,0,0)을 만들어, 위 규칙의 (0,1,1,0)을 id 개수에서 확실히 이기도록 했다(1개 id로는 (0,1,0,0)이라 class 1개 차이로 여전히 짐 — R14의 `#scr-001-scroll.screen-only-page` 사례와 달리 여기서는 상대 규칙도 이미 id 1개를 갖고 있어 id 1개로는 부족했다).
- **검증**: Playwright로 `page.emulate_media(media="print")` + `applyPrintScaling()`을 실제 실행해 인쇄 모드의 computed style을 확인 — 수정 전 `display:grid, gridTemplateColumns: 2467px 779px`(깨짐) → 수정 후 `display:block, gridTemplateColumns: 1fr`(정상)로 변경됨을 확인. 스크린샷으로 표가 전체 폭을 정상적으로 채우는 것도 확인했다. 회귀 검증으로 SCR-001을 같은 방식으로 재확인해 76%/24% 그리드가 그대로 유지됨을 확인했다(`1782px 563px` ≈ 76.0%/24.0%).
- **교훈**: `@media print`에 `!important`로 전역 규칙을 걸 때는, `.desc-wrap`이 없는 예외 레이아웃 화면(전체 폭 1단 표 등)이 있는지 항상 함께 점검해야 한다. HTML 화면에서는 인라인 스타일이 그대로 먹어 정상으로 보이므로, **PDF/PPTX 다운로드까지 직접 실행(또는 `emulate_media`로 인쇄 매체를 실제로 활성화)해서 검증하지 않으면 이런 유형의 버그는 화면 검토만으로는 절대 발견되지 않는다.**

## 4. Claude Code 작업 시 참고 사항

- **레이아웃 구조와 사이즈는 절대 변경하지 않습니다.** 헤더·캔버스·설명·푸터 4영역의 위치·비율(76%/24% 그리드)은 "1-5. 고정 사이즈/비율" 표를 그대로 따르며, 화면마다 재조정하지 않습니다.

### 5-4. PDF/PPTX 내보내기 관련 매체별 분기 규칙

- `@media print`: 실제 PDF 캡처 시 그리드 강제 유지, `.no-print`/`.download-btns` 숨김, `.screen-section`마다 페이지 분할(`page-break-before: always`)
- `.pdf-only-page`: HTML 화면에서는 숨기고(`@media screen { display:none }`) PDF/PPTX에서만 노출 — Description을 페이지 단위로 정적 분할해 보여줄 때 사용
- `.screen-only-page`(예: `-scroll` 섹션): HTML 전용 — PDF/PPT 캡처에서는 완전히 제외. CSS 특정도 문제로 반드시 **id 셀렉터**(`#scr-001-scroll.screen-only-page`)로 `@media print`에서 `display:none` 처리해야 함(클래스만으로는 상위 그리드 규칙에 밀림)
- PPTX는 `@media`를 거치지 않고 라이브 DOM을 그대로 읽으므로, `.pdf-only-page`/`.screen-only-page` 같은 화면 전용/출력 전용 분기는 `downloadPPTX()` 함수 내부에서 별도 JS 분기로 동일하게 처리되어 있음 — 신규 화면 추가 시 이 두 규칙(CSS + JS)을 함께 맞춰야 함
